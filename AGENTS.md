# AGENTS.md

Read this before touching anything. It is deliberately short — a long context
file gets skimmed, exactly like a long employee handbook.

## 1. What this is

TubePulse: evidence-backed competitor research. Paste a competitor's YouTube
channel, get their real video performance, enriched with web context, turned into
ranked video ideas with the evidence attached.

It was pitched as "voice-first" until 17 Aug 2026. That was dropped: typing a
channel URL was never the hard part, so a voice layer on top solved nothing, and
realtime audio is billed by the minute against a product priced by the scrape.
See the amendment in `docs/decisions/0005`.

Everything hangs off a **project** — competitors, outliers, ideas and transcripts
all belong to one, and a project belongs to a user.

If a change does not move that sentence forward, it is out of scope.

Longer version: `docs/product.md`.

## 2. Commands

Package manager is **npm**. Do not introduce pnpm or yarn.

```bash
npm run dev        # local dev server
npm run db:sql     # print all migrations for the Supabase SQL editor
                   # (Windows PowerShell: npm.cmd, not npm — see below)
npm run db:sql -- --from 0003   # only the ones not yet applied
npm run razorpay:plan  # create the ₹499 Pro plan at Razorpay, print its id
npm run check:env  # fail if .env.example holds a real value
npm run typecheck  # tsc --noEmit
npm run lint       # eslint
npm run test       # vitest run
npm run build      # next build
npm run check      # all four, in order — this is the gate
```

`npm run check` must pass before you open a pull request. Not "should" — must.
If it fails, fix it; if you cannot, say so in the PR body rather than
disabling the check.

## 3. Non-negotiables

- **Real values go in `.env.local`, never `.env.example`.** `.env.example` is
  committed publicly and must stay blank. `npm run check:env` enforces this and
  runs as the first step of `npm run check` and CI — because the rule has been
  broken twice, and a rule that only lives in a README is a rule that gets
  broken.
- **No secrets outside `src/lib/`.** Server secrets are read through
  `serverEnv()` in `src/lib/env.ts`, never `process.env` directly. That file is
  `server-only`, which turns a leak into a build error.
- **Every table has row-level security**, enabled in the same migration that
  creates the table. Never retrofitted.
- **The service-role key is only for the two webhooks.** Apify and Razorpay —
  both public endpoints with no user session to act as. Everywhere else uses
  `createServerClient()` so RLS applies. Reaching for the admin client to "make
  a query work" means an RLS policy is missing — fix that instead. That list
  does not grow again without a decision record.
- **Nothing from a browser may grant Pro.** `subscriptions` has a select policy
  and no insert/update/delete policy at all. It is written only by a Razorpay
  payload whose HMAC signature has been verified. See `docs/decisions/0005`.
- **Every price comes from `src/lib/billing/plans.ts`.** No page types a rupee
  figure as a literal. The old pricing page advertised ₹399 for 30 scrapes while
  the intended plan was ₹499 for 15 — a marketing page that contradicts the
  charge is a refund, not a copy problem.
- **No colour literals in components.** Use the theme tokens: `bg-background`,
  `text-foreground`, `border-border`, `text-muted-foreground`. The theme lives
  in `src/app/index.css` and is generated by TweakCN.
- **Raw scraper output never reaches the database.** It passes through a zod
  schema in `src/lib/schemas/` first. See `docs/decisions/0003`.
- **Slow work never blocks a request.** Anything over a few seconds goes through
  the jobs table. See `docs/decisions/0002`.
- **`src/components/ui/` is shadcn's, not ours.** Do not hand-edit those files;
  they get overwritten. Compose around them in `src/components/`.

## 5. Definition of done

1. `npm run check` passes.
2. Docs updated **in the same pull request** — stale docs are worse than none,
   because the next agent trusts them.
3. If the schema changed: a new migration file, `src/lib/supabase/types.ts`
   updated to match, RLS on the new table.
4. PR body follows `.github/pull_request_template.md`.
5. One concern per PR. "Add scraping and refactor auth" gets split.

## 6. Known traps

This list grows every time something slips through. Adding to it is part of
fixing a bug — the code fix alone is half the job.

- **`lucide-react` v1 removed brand icons.** No `Github`, no `Twitter`. Use a
  generic icon or an inline SVG.
- **Supabase `Database` types must be `type`, not `interface`.** Interfaces do
  not get implicit index signatures, so the generic silently resolves to `never`
  and every query loses its types.
- **Each table in `Database` needs a `Relationships: []` key.** Same failure
  mode as above.
- **Apify actors return `null` where you expect a missing key.** Raw schemas use
  `.nullish()`, not `.optional()`. A test caught this dropping valid videos.
- **`src/lib/env.ts` is `server-only`.** Client components import
  `src/lib/public-env.ts` instead. Importing the wrong one breaks the build.
- **Next 16 route params are a Promise.** `const { id } = await params`.
- **On Windows PowerShell, run `npm.cmd`, not `npm`.** The default execution
  policy is Restricted, which blocks `npm.ps1` with an UnauthorizedAccess error
  that looks like a broken install. `npm.cmd` sidesteps it entirely.
- **The logo is not ours to redraw.** `public/brand/` holds the supplied
  artwork; `components/brand/logo.tsx` renders it and nothing else. Do not
  substitute a hand-drawn SVG version.
- **`src/app/index.css` holds the user's TweakCN paste.** Add project CSS only
  in the marked block at the bottom, never inside their theme region.
- **The brand gradient is `--brand-1/2/3`.** Never hardcode the violet, magenta
  or red — every gradient reads those three tokens.
- **Auth needs three Supabase dashboard settings** that are not in this repo:
  custom SMTP, the `{{ .Token }}` email template and the Google provider. Free
  projects created after 3 June 2026 cannot edit email templates at all until
  custom SMTP is configured — the body is silently read-only, with no error
  saying why. See `docs/auth-setup.md` before debugging a "code never arrives"
  report.
- **Every sign-in path must honour `next`, including the 6-digit code.**
  Password sign-in and the Google callback always did; `signUpWithPassword` and
  `verifyEmailCode` did not — the first never forwarded `next` to
  `/login/verify`, and the second ended with a hardcoded `redirect("/projects")`.
  So anyone who clicked Go Pro, signed up, and typed the code landed in the
  workspace instead of back at checkout. All three paths now route through
  `safeNext()`. Adding a fourth entry point means threading `next` through it too.
- **`getUser()`, never `getSession()`, in middleware.** getSession trusts the
  cookie without revalidating it.
- **Apify REJECTS a run whose webhook URL it cannot reach.** It validates
  `requestUrl` at creation and fails the whole run — it does not quietly skip
  the webhook. `http://localhost:3111/api/webhooks/apify` therefore broke every
  local scrape with an error naming the webhook rather than the cause.
  `webhooksCanReachUs()` in `lib/apify/reachable.ts` gates whether a webhooks
  array is sent at all; on a dev machine none is, and `/api/jobs/[id]/sync`
  finishes the job. That rule lives in its own pure file because `client.ts` is
  `server-only` and a test cannot import it — same reason as
  `lib/auth/messages.ts`.
- **Apify ingest lives in one module.** `lib/apify/ingest.ts` is shared by the
  webhook and the sync route. Never inline a second copy — the divergence only
  reproduces on one machine.
- **The model is `OPENAI_MODEL` in env, not a constant.** Provider model names
  get renamed; that should be a `.env` edit, not a deploy.
- **JSON mode guarantees valid JSON, not our shape.** The zod check after the
  OpenAI call is not redundant. Never remove it.
- **WebGL is allowed in the workspace; scroll hijacking is not.** Amended
  17 Aug 2026. `three` and GSAP may be used under `(workspace)/` for ambient
  depth, reveals and data visualisation. **Lenis must not be** — the signed-in
  app keeps NATIVE scrolling. Fighting a data table to scroll is misery by day
  three, and that half of the old rule was the load-bearing half.
  Anything WebGL in the workspace must also: lazy-load (never in the first
  paint), pause on blur, honour `prefers-reduced-motion` with a static frame,
  and cap device pixel ratio. It is a tool people keep open all day, not a page
  they visit once.
- **Lenis and ScrollTrigger must be bridged.** Lenis interpolates scroll while
  ScrollTrigger reads the native position; unbridged they sit a frame apart and
  every pinned section judders. `smooth-scroll.tsx` wires Lenis into GSAP's
  ticker. Do not mount one without the other.
- **Landing animation is opt-in via data attributes,** read by
  `scroll-choreography.tsx`. Do not import GSAP into a section component — the
  page's timing language is defined once, on purpose.
- **The landing page makes no claim that is not in `docs/product.md`.** No
  invented adoption numbers. The product argues evidence over vibes; the
  marketing page does not get an exemption.
- **Reveal animations must use `gsap.fromTo`, never `gsap.from`.** The CSS start
  state is `opacity: 0`; `from()` reads the CURRENT value as its destination, so
  it animates 0 -> 0 and the element is invisible forever. Two whole sections
  shipped blank this way. State the end explicitly.
- **Never hand-write a Tailwind group selector.** `[.group\/tilt:hover_&]:`
  emitted CSS that Turbopack refused to parse, and it failed the build while
  passing both typecheck and lint. Use the named-group variant
  (`group-hover/tilt:`). Corollary: `typecheck` + `lint` passing does not mean
  the page renders — run `build`, or load it.
- **Write migrations so a re-run is a no-op.** `create table` and `create type`
  have no `IF NOT EXISTS`, so re-running one answers `42P07: relation already
  exists` — which reads as a broken migration when it actually means "already
  done". 0008 did that. Use `add column if not exists`, `create index if not
  exists`, and a `do $$ ... exception when duplicate_object then null; end $$`
  block around `create type` and `create policy`.
- **Migrations that touch an enum are pasted ALONE.** `ALTER TYPE ... ADD VALUE`
  can be rejected with "cannot run inside a transaction block", and the Supabase
  SQL editor sends a pasted block as one string. `npm run db:sql -- --only 0008`
  prints exactly one migration for this reason.
- **The logo is rendered at `quality={100}`.** Next re-encodes at 75 by default,
  which is fine for a photograph and visibly wrong for a smooth violet-to-red
  gradient — it put banding through the wordmark and read as blurry in the
  sidebar. `sizes` is a per-placement prop too: the same artwork is drawn at
  32px tall in the sidebar and 200px wide in the preloader, and one shared
  `sizes` asked for the wrong resolution in both.
- **The workspace entrance animation lives in TWO shared components, not ten
  pages.** `RevealGroup` inside `WorkspacePanel` staggers each page's sections;
  `Tilt` inside `StatGrid` gives the tiles their lean. Adding it per page is how
  ten copies drift. Its hidden state is set by JAVASCRIPT, never CSS — the
  server sends visible markup, so a bundle that fails to load costs the
  animation and not the page.
- **Instagram reuses `channels` and `videos`, tagged with `platform` and
  `kind`.** Not parallel tables — outliers, ideas, projects and the jobs
  pipeline already work on those two, and a second set would mean a second copy
  of all of it. What differs is carried by the two columns.
- **Reels and static posts are scored in SEPARATE POOLS, on DIFFERENT metrics.**
  A reel is measured in plays and routinely passes ten times the follower count;
  a photo is measured in likes. Pooled, one reel at 11M plays makes every photo
  on the account read as a failure — the same damage Shorts do to a YouTube
  median. `scoreVideos` takes one median per `kind` and `metricOf` picks the
  metric. Never "simplify" that back to a single pool.
- **A static post has NO view count, and that is not zero.** `videos.view_count`
  is nullable since 0009 for exactly this. Zero is a claim that nobody watched
  something that is not watchable, and it would drag every median it touched.
  The table prints likes for those rows, labelled.
- **Instagram costs 4-6x YouTube per item** — measured, $0.0027 against roughly
  $0.00045. That is why `postsPerScrape` is 40 while `videosPerScrape` is 100:
  40 posts is ₹9.5, inside the ₹12 the margin sums assume, and 100 would be
  ₹24 — an allowance spent entirely on Instagram would cost ₹480 against ₹499.
  **Move the depth, never the price.**
- **The owner of an Instagram post is not always the account you scraped.**
  Collab posts carry the partner's `ownerUsername`: the captured NASA run was 8
  nasa, 1 spherevegas, 1 astro_jessica, and taking the first post's owner named
  the channel "Sphere". `normalizeInstagramDataset` takes the MAJORITY owner.
- **Hashtag and location URLs are refused on purpose.** The actor would happily
  scrape a tag feed, but a tag's posts belong to hundreds of accounts and a
  median over them means nothing. `parseProfileInput` rejects `/explore/` and
  single-post links with a reason, not a generic error.
- **The pasted URL beats the platform toggle.** Someone pasting an
  instagram.com link while the selector says YouTube means Instagram. The
  selector only decides a bare handle like `@nasa`, which is valid on both.
- **A transcript actor that rejects its input still reports SUCCEEDED.** Send
  the wrong input key and `supreme_coder/youtube-transcript-scraper` finishes
  happily, writing one dataset item: `{ errorCode: "NO_VIDEOS_FOUND" }`. The run
  looks fine, the webhook fires normally, and the only symptom is an empty
  transcript — which the first version reported as "no captions came back for
  that video", sending you to inspect the one place the problem was not.
  `transcriptError()` is checked BEFORE the empty-text branch for this reason.
  **The input key is `urls: [{ url }]`**, not `startUrls`, not `videoUrl`.
- **Guessing an actor's output shape does not work. Capture one run.** The
  transcript normalizer was written from assumptions and shipped four bugs:
  the input key, a nested `videoDetails.title`, a nested `videoDetails.videoId`,
  and text arriving HTML-escaped (`We&#39;re`). One real run against the API
  found all four in a minute. `tests/fixtures/transcript-run.json` is that run,
  and the tests against it are what keep the feature honest — same rule the
  channel normalizer already followed.
- **Caption text is HTML-escaped and must be decoded.** `decodeEntities()` runs
  before storage, so `&#39;` never reaches the page OR the summariser, which
  would otherwise be reading entity codes as if they were words.
- **The transcript actor is swappable, and the normalizer is why.** There is no
  agreed output shape for a captions actor: the same data comes back as a
  string, an array of timed segments, one dataset item per caption line, or
  nested under `data`. `lib/schemas/transcript.ts` accepts all of them, so
  changing actor is an `.env` edit rather than a code change. The input side
  sends `videoUrl`, `videoUrls` AND `startUrls` for the same reason — actors
  ignore keys they do not know.
- **A blank `APIFY_TRANSCRIPT_ACTOR` switches the page off, it does not crash
  it.** It defaults to `""` rather than being required, because `serverEnv()`
  validates the WHOLE schema on first call — making it mandatory would take down
  every route on a machine that has not set transcripts up, exactly the way a
  blank `OPENAI_API_KEY` once hid the Go Pro button. `isTranscriptConfigured()`
  is how the page asks.
- **A failed summary must not lose the transcript.** `summariseTranscript()`
  returns null instead of throwing. The transcript is what the button was
  pressed for and it already exists by then; throwing would trade it for a
  convenience. Same rule as Firecrawl enrichment — optional things degrade.
- **Three job kinds spend the allowance, not one.** A scrape pays Apify; an idea
  generation pays OpenAI and Firecrawl; a transcript pays Apify for the captions
  and OpenAI for the summary. All three cost money per press, so all three are
  counted — the list is `BILLABLE_JOB_KINDS` in `lib/billing/quota.ts`, and
  `getQuota()` counts `jobs` rows of those kinds. A NEW JOB KIND IS FREE UNTIL
  IT IS ADDED THERE, and that failure is silent and in the customer's favour, so
  nothing ever complains. `/api/ideas` therefore writes a job row even though
  nothing polls it: the row IS the charge. It marks that row `failed` on every
  error path, because a failed job is not counted and work that produced nothing
  must not be billed.
- **Quotas are enforced at the three routes that spend money: research, ideas
  and transcript — nowhere else.** `getQuota()` is checked before any row is written in
  both, because the allowance is counted from `jobs` and a refused request must
  not leave a job behind. Two pools, and the
  order matters: the plan allowance (20/month Pro, 5 ever on Scout, counted from
  `jobs`) is spent before refills (bought outright, negative rows in
  `scrape_credits`). Never write a ledger row for an allowance scrape — it is
  already counted, and doing both charges twice.
- **The allowance resets on the subscription's day of the month, not the 1st.**
  Anchoring to the 1st would give someone who subscribed on the 28th a full 20
  for three days and 20 more on the 1st — double the scrapes for one payment,
  straight out of the margin. `periodStartFor()` clamps a 31st anchor into short
  months. Yearly subscribers reset monthly too: the allowance is 20 a MONTH
  whichever cycle they pay on.
- **402 means buy something; 429 means wait.** The research route returns 402
  when scrapes have run out and 429 when only the daily cap is hit. Telling
  someone to come back tomorrow when tomorrow brings nothing is the failure this
  split avoids.
- **Annual billing is a SECOND Razorpay plan,** not a discount on the monthly
  one. A Razorpay plan hard-codes its period AND its amount, so there is no way
  to bill a monthly plan yearly. `npm run razorpay:plan` creates both.
  `RAZORPAY_PLAN_ID_PRO_YEARLY` is optional — blank simply hides the toggle.
- **Yearly is two months free, and that costs 9 points of margin.** 49% monthly
  against 40% yearly worst case, because costs do not fall when someone
  prepays. A test fails below 35%. Deepening the discount walks into the
  thirties.
- **A subscription promo needs a Razorpay OFFER; a refill promo does not.**
  Refills are Orders and are created for whatever amount we say, so their
  discount is ours to compute. A subscription bills a fixed-amount plan and can
  only be discounted through an Offer created in the Razorpay dashboard, passed
  as `offer_id`. A subscription-scoped code with no `razorpay_offer_id` is
  REJECTED at validation — never show a discount and then charge full price.
- **The promo preview endpoint grants nothing.** `/api/billing/promo` is a
  preview for struck-through prices; checkout and topup re-validate the code
  server-side. Never trust a discount figure that came from a browser.
- **A discounted refill is not underpaid.** The order carries `charged_paise` in
  its notes, and that — not the catalogue price — is what the webhook and the
  confirm route compare the payment against. Comparing to the list price
  rejects every promo purchase.
- **Refills must cost MORE per scrape than Pro.** Rs 24.95 on the plan versus
  about Rs 30 in a pack. A refill that undercuts the subscription teaches people
  to cancel the subscription. A test enforces it — do not "round the prices
  nicely" past it.
- **`scrape_credits` is an append-only ledger, not a balance.** Purchases are
  positive rows, spends will be negative, and the balance is their sum via the
  `scrape_credit_balance` view. A single counter column would lose updates under
  concurrency and silently give away or steal scrapes.
- **Granting a refill is idempotent by unique index,** on
  `scrape_credits.razorpay_payment_id` — not by checking first. Three paths
  (browser confirm, `order.paid` webhook, manual sync) all insert; the
  constraint is what stops a pack being granted three times.
- **Cancel Razorpay BEFORE writing the local row.** `/api/billing/cancel` does
  it in that order deliberately. Reversed, the app says "cancelled" while the
  mandate keeps debiting Rs 499 a month — the worst bug a billing system has.
- **The webhook signature is over the RAW body.** Read `request.text()` and
  verify before parsing. Calling `request.json()` and re-stringifying changes
  the bytes and no signature will ever match. This is the single most common
  Razorpay integration bug and it looks exactly like a wrong secret.
- **Everything at Razorpay is per-mode.** Keys, plans, offers and webhook
  secrets exist separately in test and live, so switching mode means replacing
  six env values, not two. A test plan id beside a live key fails with "plan not
  found", which names nothing. `razorpayMode()` reads the key prefix,
  `/billing` shows a test-mode notice, and a production build refuses to start
  on test keys — because shipping test keys live looks perfect and silently
  earns nothing.
- **A blank `OPENAI_API_KEY` hides the Go Pro button.** `serverEnv()` validates
  the WHOLE schema on first call and throws naming any missing variable;
  `isBillingConfigured()` catches that throw and returns false, so the upgrade UI
  and refill cards disappear. Nothing on screen connects an LLM key to payments,
  and the button is simply absent rather than disabled. The Razorpay keys default
  to `""` precisely to avoid this class of coupling — `OPENAI_API_KEY` does not.
  `billingConfigProblem()` now returns the real reason and dev logs
  `[billing] Upgrade UI is HIDDEN. …` on first check. Read that line before
  hunting for a missing button.
- **Do not verify a guard by reimplementing it.** Checking the four Razorpay
  names with a standalone script reported "all set" while the real
  `isBillingConfigured()` returned false, because the script never called
  `serverEnv()` and so never hit the throw. Call the actual function, or read
  the actual page.
- **`RAZORPAY_WEBHOOK_SECRET` gates the BUTTONS, not just the webhook.**
  `requireBillingEnv()` lists it among the four required values, so with it blank
  `isBillingConfigured()` is false and `/billing` and `/pricing` silently hide
  Go Pro and disable the refill cards. It reads as "the button is missing", not
  as "a variable is unset". The secret is invented by us, not issued by Razorpay
  — generate one and paste the same string into the dashboard at deploy time,
  rather than leaving it blank until then.
- **Placeholder env values survive a rebuild from `.env.example`.**
  `NEXT_PUBLIC_SUPABASE_URL` sat at `https://yourproject.supabase.co` while
  `SUPABASE_URL` was correct; that host does not resolve and Node reports it only
  as `fetch failed`. Both `supabase/client.ts` and `supabase/server.ts` read the
  PUBLIC one, so a single wrong value breaks browser and server auth together.
  `check:env` guards `.env.example`, never `.env.local` — grep for placeholder
  strings there too, not just empty values.
- **`RAZORPAY_KEY_ID` exists twice, on purpose.** The browser needs the
  publishable half to open checkout, so it is also
  `NEXT_PUBLIC_RAZORPAY_KEY_ID`. `RAZORPAY_KEY_SECRET` must NEVER gain that
  prefix — it would ship in the JavaScript bundle.
- **Razorpay plans cannot be edited or deleted.** Repricing means running
  `npm run razorpay:plan` again and repointing `RAZORPAY_PLAN_ID_PRO`. Existing
  subscribers stay on the old plan until they resubscribe.
- **Razorpay has no "until cancelled".** `total_count` is mandatory on a
  subscription; we send 100 monthly cycles. See `PRO_TOTAL_CYCLES`.
- **The Rs 499 price survives gpt-4o, but 20 scrapes is the ceiling.** One
  scrape costs about Rs 12 on gpt-4o versus Rs 6 on a mini model; 20 scrapes
  leaves 49% on the expensive model, 74% on the cheap one. Every extra scrape
  costs Rs 12 and earns nothing — 25 would drop it to 37%, 30 to 25%. Raise the
  price, not the allowance. A test in `tests/billing-status.test.ts` fails below
  45%, so `OPENAI_MODEL` is no longer a pricing decision. The Rs 399/30 version
  was.
- **`/project` is the hub; the project id stays in a COOKIE, not the URL.**
  Clicking a project on `/projects` sets `tp_project` and lands on `/project`,
  which is why every workspace page keeps a clean path (`/outliers`, never
  `/projects/<uuid>/outliers`). The cookie is only a hint — `getCurrentProject()`
  re-resolves it under RLS every time, so a tampered one resolves to nothing.
- **The hub tells you ONE next thing, not six.** `lib/projects/next-step.ts` is
  pure and ordered: a running job outranks a past failure, a failure outranks
  advice, and being out of scrapes only surfaces when the next step actually
  needs one — nagging about billing before a free action is noise. Being told
  six things is the same as being told nothing.
- **The daily cap governs the ALLOWANCE, not scrapes already bought.** A user
  who paid for a refill and was told "that is your 5 for today, more tomorrow"
  is a refund waiting to happen. Past the cap the work still runs and is charged
  to the refill ledger — `mustSpendRefill` on the Quota carries the rule so the
  three spending routes cannot drift. The guard is intact: the allowance itself
  is still capped, so it cannot be emptied in under four days, and a refill
  earns about ₹30 a scrape against a cost under ₹10, so heavy refill use is
  profitable rather than dangerous.
- **The Pro daily cap must stay below scrapes/3.** It is 5 against a monthly 20,
  so the month cannot be drained in under four days. A cap of 7 was tried and
  reverted: 7 over three days exceeds 20, which made it a burst limit rather
  than a spend guard. Raising it re-opens the surprise-bill hole.
- **The nav lives in `components/landing/site-nav.tsx`,** used by both public
  pages. It was duplicated once and the two copies drifted within a day.
- **Supabase SMTP must use port 587, not 465.** 465 is implicit TLS, which
  Supabase's auth service handles badly and which free Gmail rejects outright.
  The only symptom is a generic `Error sending confirmation email`; the real
  reason is in the dashboard under Logs → Auth Logs.
- **The email code length lives in `src/lib/auth/otp.ts`.** It must match the
  Supabase dashboard's *Email OTP Length*. It was previously inlined as `6` in
  six places and drifted against a dashboard set to 8 — the form was a digit
  short and the error blamed the code. Never inline the number.
- **Supabase returns one string for a wrong code and an expired one:**
  `Token has expired or is invalid`. Do not test `/expired/` before that
  combined form, or every mistyped code reports as expired. See
  `src/lib/auth/messages.ts`, which is pure and tested precisely because
  `actions.ts` is `"use server"` and cannot export a sync function.

## 7. Stop and ask

Do not do these without checking first:

- Changing the database schema in a way that drops or renames a column
- Creating or changing a promo code (it spends real margin)
- Anything touching auth, or the pricing/quota numbers in `lib/billing/plans.ts`
  (the Razorpay wiring itself is now built — see `docs/billing-setup.md`)
- Adding a paid dependency or a new external service
- Raising a timeout instead of moving work to the jobs table
- Editing a migration that has already been applied
