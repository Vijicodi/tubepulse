# Building UI

## Never hardcode a colour

The theme lives in `src/app/index.css` and is generated by TweakCN. Every colour
in the app comes from a token:

```tsx
<div className="bg-card text-card-foreground border-border">   // correct
<div className="bg-white text-gray-900 border-gray-200">       // WRONG
```

Tokens available: `background`, `foreground`, `card`, `popover`, `primary`,
`secondary`, `muted`, `accent`, `destructive`, `border`, `input`, `ring`,
`chart-1` … `chart-5`, `sidebar*`. Each has a `-foreground` pair where relevant.

**Why this is strict:** the user swaps the whole theme by pasting a new TweakCN
block into `index.css`. One hardcoded colour and that swap produces a page with
one wrong element, which is worse than a page that is entirely the old theme.

This also gets dark mode for free. Every token has a `.dark` value already.

## `src/components/ui/` is not ours

Those files are shadcn's. `npx shadcn@latest add <x>` overwrites them without
asking. Do not hand-edit them.

Need different behaviour? Compose around the primitive in `src/components/`:

```
src/components/ui/button.tsx                shadcn's — leave alone
src/components/generate-ideas-button.tsx    ours — wraps Button
```

## Check before adding

shadcn components already installed: `button`, `card`, `input`, `badge`,
`skeleton`, `separator`, `progress`, `sonner`, `table`, `tabs`, `avatar`.

Add more with `npx shadcn@latest add <name>` — do not hand-write a component
that shadcn already ships.

## Icons

`lucide-react` v1 **removed all brand icons**. There is no `Github`, no
`Twitter`, no `Youtube`. Use a generic icon or an inline SVG. This has already
broken a build once.

## Server by default, client when needed

Components are server components unless they need state, effects, or event
handlers. `"use client"` is a cost — it ships JavaScript — so push it down to
the smallest component that actually needs it.

Current split, as a model:

- `channels/[id]/page.tsx` — server, does the queries under RLS
- `video-table.tsx`, `idea-list.tsx` — server, pure presentation
- `research-form.tsx`, `job-status.tsx` — client, they have state and realtime

## Honest UI

From `docs/product.md`, and these are product decisions, not style:

- The progress bar is an elapsed-time estimate and the label says so. Apify does
  not report percentages; inventing one would be a lie.
- Idea confidence shows what the model reported, including low numbers.
- Error messages say what went wrong and what to do — never "Something went
  wrong".

## Accessibility floor

- Every icon-only control gets an `aria-label`
- Decorative icons get `aria-hidden`
- Inputs get a label or `aria-label`
- Do not remove focus rings; the theme already styles them via `outline-ring/50`
